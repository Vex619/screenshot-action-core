# Contributing

Thanks for helping improve Screenshot → Action Core.

## Before opening a PR

1. Read the README and existing issues.
2. Keep provider-specific integrations behind adapters.
3. Add or update tests for behavior changes.
4. Run `pytest` and `ruff check .` locally.
5. Keep public schemas backwards compatible when practical.

## Pull requests

Describe the user problem, implementation approach, tests added, and any compatibility considerations. Small, focused PRs are preferred.

## Security-sensitive changes

Do not include real credentials, private screenshots, payment information, authentication codes, or personal data in tests or examples.
